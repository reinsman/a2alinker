# 架构与适配器接口约定

`a2alinker` 是一个同时提供库和命令行工具的 Rust 包。每个实例在启动时确定
agent 类型、执行配置、工作目录，以及选中技能的快照。

## 模块划分

| 模块 | 职责 |
| --- | --- |
| `cli`、`config` | 命令选择、配置优先级、路径解析和校验 |
| `skills` | 发现可移植的技能包、校验名称、按内容建立快照 |
| `adapters` | 加载原生配置、继承认证信息、管理协议会话 |
| `adapters::process` | 限制 JSONL 报文大小、持续消费进程管道、管理进程组 |
| `runtime` | 有界任务队列、会话互斥、任务状态机和取消操作 |
| `storage` | SQLite 事务、快照、消息去重和存储目录独占锁 |
| `a2a` | A2A 1.0 协议绑定、能力发现、bearer 认证和 SSE |

对外协议类型来自 `ra2a = 0.10.1`。任务接收、原生会话、消息去重和事件提交由
应用自身管理，与 SDK 的执行器和任务存储实现保持独立。

## 标识与执行流程

- `contextId` 对应一个原生 pi 会话文件或 Codex thread。客户端提供的会话标识
  不会直接用于拼接文件路径；pi 会话文件名使用该标识的哈希值。
- `taskId` 由网关生成，标识某个会话中的一项工作任务。
- `runId` 保存在任务元数据中，标识一次原生执行尝试。
- `messageId` 在实例的单一信任域内持久化。重复使用同一标识时，规范化后的
  消息内容必须完全一致。`returnImmediately` 等传输选项不会触发新的执行。

任务接收通过互斥锁串行处理。网关先预留队列容量，再提交任务和消息记录，
然后将任务交给执行器。一个执行器持有原生会话，每次只运行一个任务。
向已有未结束任务的会话提交新任务时，会明确返回忙碌响应。

每次任务更新及其对应事件都在同一个 SQLite 事务中提交。订阅时，在同一个
事务中读取任务快照和最新事件游标，然后只流式发送该游标之后的事件。
广播通知仅用于唤醒订阅者；数据库中的记录才是事件的权威来源。
重新连接时先返回新的完整快照，避免客户端重复应用旧的增量。

当前仅使用 `TASK_STATE_INPUT_REQUIRED` 表示等待原生审批或用户输入。
遇到不支持的凭据刷新或其他服务端请求时，会明确报错。
网关目前不负责自动获取 OAuth 授权。

## 新增 agent 适配器

1. 在 `AgentKind` 中增加类型，并在 `src/adapters` 下添加对应模块。
2. 实现 `AgentSession` 的 `native_id`、`is_alive` 和异步 `run` 方法。
3. 在 `adapters::create_session` 中注册会话创建逻辑，并更新命令行的适配器列表。
4. 将原生事件流转换为 `AgentEvent`，原生协议类型保留在适配器内部。
   只可转发上游主动公开的思考文本或摘要；不尝试获取隐藏推理、签名或加密内容。
5. 明确真正表示执行完成的事件、取消操作，以及可用于恢复会话的原生标识。
   命令已被接收的响应不代表执行完成。
6. 如果支持原生用户交互，补充响应校验器，并记录请求和响应格式。
   对不支持的服务端请求明确返回错误。
7. 添加子进程测试替身和集成测试，覆盖完成、恢复、取消、超时、无效报文、
   错误以及相关交互行为。
8. 对已安装的运行时执行 `doctor`，验证真实接入，但不发起模型推理请求。

`OutputDelta` 向 `item_id` 对应的产物追加内容。`OutputComplete` 使用原生协议
返回的最终消息替换该产物已累积的文本，防止流式文本重复显示。
`Reasoning` 将上游公开的思考文本保存到独立产物，元数据标记为 `reasoning`。
思考不会混入最终回答的聊天历史。`Tool` 将工具开始、累计输出和结束事件转成
结构化状态消息，以原生 `toolCallId` 关联；任务历史为每次调用保留最新快照。
参数、结果和思考文本均受 `max_output_bytes` 限制。关闭对应配置后不写入任务
或事件数据库。当前 pi 适配器提供这些过程事件，详见 [执行过程协议](execution.md)。

网关通过取消令牌通知适配器。适配器发送原生中断请求后，继续读取事件，
直到收到真正的完成事件。运行时还会强制执行取消超时限制，即使原生启动命令
尚未确认接收，也能终止等待。释放会话时，会终止其独立的 Unix 进程组。

会话进程会因空闲超时或达到配置的数量上限而被释放，原生会话标识仍保留在
SQLite 中。配置和技能的内容指纹用于防止旧会话在未明确告知的情况下切换
执行配置。原生会话丢失时会报错，不会静默新建空白会话。

## 首版实现范围

每个实例对应一个信任域和一个工作目录。在支持独立工作目录或 worktree 之前，
配置校验会拒绝并行执行。目前支持文本输入与输出，以及结构化交互回复；
二进制产物和生成文件的下载能力需要单独的产物存储服务。

原生 CLI 及其依赖需要与 Rust 二进制程序分别部署，适配器通过各 agent 的
集成接口接入。外部可执行适配器、带版本号的插件通信协议、其他 A2A 协议绑定、
推送通知、并发插入时仍保持稳定的分页，以及保留期限和垃圾回收机制，均属于
后续扩展范围。当前 `ListTasks` 使用偏移量游标，假定翻页期间结果集保持稳定，
不能将其作为持久化的增量同步游标。
