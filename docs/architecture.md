# Architecture and adapter contract

`a2alinker` is a single Rust package with a library and a CLI. An instance fixes its
agent kind, configuration, working directory and selected skill snapshot at startup.

## Modules

| Module | Responsibility |
| --- | --- |
| `cli`, `config` | Command selection, precedence, path resolution and validation |
| `skills` | Discover portable packages, validate names and build content snapshots |
| `adapters` | Native configuration, authentication inheritance, protocol sessions |
| `adapters::process` | Bounded JSONL framing, continuous pipe consumption, process groups |
| `runtime` | Bounded queue, context exclusion, task state machine and cancellation |
| `storage` | SQLite transactions, snapshots, message deduplication and exclusive storage lock |
| `a2a` | A2A 1.0 binding, discovery, bearer authentication and SSE |

The public protocol types come from `ra2a = 0.10.1`. The SDK's executor and task
store are deliberately behind the boundary: this application controls admission,
native sessions, deduplication and event commits itself.

## Identity and execution

- `contextId` identifies a native pi session file or Codex thread. Client-provided
  context IDs never become filesystem path components; pi paths use their hash.
- `taskId` is generated by the gateway for a unit of work within a context.
- `runId` identifies the native execution attempt in task metadata.
- `messageId` is durable within the instance's single trust domain. Duplicate IDs
  must carry exactly the same normalized message. Transport options such as
  `returnImmediately` do not create a new execution.

Admission is serialized by a mutation lock. A queue permit is reserved before the
task and message are committed, then the work item is handed to the worker. One
worker owns the native sessions and runs one task at a time. Submitting a new task
to an already-active context returns an explicit busy response.

Each task update and its event are committed in the same SQLite transaction.
Subscriptions read the task snapshot and latest event cursor in one transaction,
then stream events strictly after that cursor. Broadcast messages only wake readers;
the database is the authoritative event source. Reconnection begins with a new
complete snapshot, avoiding double application of old deltas.

The only currently emitted interrupted state is `TASK_STATE_INPUT_REQUIRED` for
native approval or input requests. Unsupported credential-refresh and other server
requests fail explicitly. Automatic OAuth provisioning is outside the gateway.

## Adding another agent

1. Add a kind to `AgentKind` and a module under `src/adapters`.
2. Implement `AgentSession`: `native_id`, `is_alive`, and asynchronous `run`.
3. Register session creation in `adapters::create_session` and the CLI inventory.
4. Translate the native stream into `AgentEvent` values. Keep native protocol types
   inside the adapter. Never expose provider chain-of-thought as output artifacts.
5. Define the actual completion event, cancellation operation and resumable native
   identifier. A command acceptance response is not a completion event.
6. If native user interaction is supported, add its response validator and document
   its request/response shapes. Reject unsupported server requests explicitly.
7. Add subprocess fixtures and integration tests for completion, resumption,
   cancellation, timeouts, bad frames, errors and any interaction behavior.
8. Run `doctor` against the installed runtime without making an inference request.

`OutputDelta` appends to an artifact identified by `item_id`. `OutputComplete`
replaces that artifact's accumulated text with the native authoritative message,
preventing streamed text from appearing twice. Native reasoning events are ignored.

The gateway sends a cancellation token into the adapter. Adapters request a native
interrupt and continue reading until the actual completion event. The runtime also
enforces a hard cancellation deadline, including when a native start command has
not acknowledged. Dropping a session kills its dedicated Unix process group.

Sessions are evicted by idle timeout or the configured maximum count. Their native
identifiers stay in SQLite. Configuration and skill fingerprints prevent an old
context from silently changing execution profiles. A missing native session is an
error rather than a new empty conversation.

## Deliberate first-version boundaries

The instance is one authenticated trust domain and owns one workspace. Configuration
validation rejects parallel execution until independent workspaces/worktrees exist.
The supported input/output formats are text plus structured interaction replies;
binary artifacts and downloadable generated files need a separate artifact store.

Native CLIs and their dependencies are deployed separately from the Rust binary.
The adapters use an integration API, not a Rust implementation of the agents.
External executable adapters, a versioned plugin transport, additional A2A bindings,
push notifications, stable pagination across concurrent inserts and retention/GC
are future extensions. The current `ListTasks` offset cursor assumes a stable result
set between pages; do not treat it as a durable synchronization cursor.
